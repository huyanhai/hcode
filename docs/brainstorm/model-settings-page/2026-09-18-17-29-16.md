# HCode 模型设置页设计

## 状态

已获批准的设计。本文档定义模型设置页的页面结构、状态保留方式和模型查询协议。

## 背景

HCode 已支持多个本地模型配置，但配置表单位于聊天页右侧栏。新设计将配置能力迁移到独立设置页。用户从聊天页左下角进入设置页，返回后聊天页保持进入前的状态。

## 目标

- 在当前 Electron 窗口内打开独立设置页。
- 设置页左侧显示设置菜单，首版只有“模型配置”。
- 设置页右侧管理多个 Provider 配置。
- 根据 Base URL 和 API Key 请求模型列表。
- 返回聊天页时保留会话、输入草稿、滚动位置和面板状态。
- API Key 仅由 Agent Runtime 和本地数据库读取。

## 非目标

- 首版不提供常规、外观、快捷键等其他设置菜单。
- 首版不打开新的 Electron BrowserWindow。
- 首版不在 Renderer 中直接请求 Provider。
- 首版不改变 API Key 明文存储方案。

## 页面与路由

新增 /settings 路由。聊天页继续使用 /。

App.vue 通过 RouterView 的插槽渲染页面，并使用 KeepAlive 缓存聊天页。进入设置页时，聊天页停用但不卸载；返回后继续使用原组件实例。

左下角“设置”按钮执行路由跳转。设置页左上角“返回应用”回到 /。返回操作不重新创建聊天页面。

## 页面结构

设置页使用全窗口双栏布局，并复用现有主题变量和 apps/client/src/components/ui 组件。

### 左侧导航

- 宽度在桌面端保持稳定，不随内容伸缩。
- 顶部保留 macOS 窗口拖拽区域。
- 显示带左箭头的“返回应用”按钮。
- 菜单首版只有“模型配置”，并保持选中状态。
- 为后续设置项保留菜单结构，不展示无功能占位项。

### 右侧内容

- 内容区独立纵向滚动。
- 页面标题为“模型配置”，下方显示简短说明。
- 配置列表展示名称、Provider、Base URL、当前模型和默认状态。
- 支持新增和编辑配置。
- 使用分组容器组织配置列表和编辑表单，不嵌套装饰性卡片。

### 配置表单

表单字段包括：

- 配置名称
- Provider
- Base URL
- API Key
- 模型
- 默认配置开关

编辑已有配置时，API Key 输入框保持为空并显示脱敏提示。用户不输入新值时保留原密钥。

“获取模型”按钮位于 Base URL 和 API Key 附近。请求期间显示加载状态并禁用重复提交。请求成功后，模型选择器展示返回的模型 ID；保存前必须选择模型。

## 模型查询协议

共享协议新增 model/list Command。请求参数为：

    type ListModelsPayload = {
      profileId?: string;
      baseUrl: string;
      apiKey?: string;
    };

新配置必须提供 API Key。编辑配置未提供新 API Key 时，Runtime 根据 profileId 读取数据库中的原密钥。

Runtime 将 Base URL 末尾的 / 去除，再请求：

    GET {baseUrl}/models
    Authorization: Bearer {apiKey}

Runtime 解析 OpenAI-compatible 响应中的 data[].id，去重并按名称排序。响应只包含模型 ID，不包含 API Key、Authorization Header 或原始响应头。

## 状态与数据流

    点击设置
      -> 跳转 /settings
      -> KeepAlive 停用聊天页
      -> 设置页读取 model_profiles 摘要

    点击获取模型
      -> Renderer 发送 model/list
      -> Runtime 解析密钥并请求 /models
      -> Renderer 展示模型选项或错误

    保存配置
      -> Renderer 发送 profile/upsert
      -> Runtime 写入 SQLite
      -> 刷新模型配置摘要
      -> 聊天输入框同步最新模型列表

    点击返回应用
      -> 跳转 /
      -> KeepAlive 激活原聊天页实例

设置页的临时表单状态属于页面组件。已保存配置和聊天数据继续由 Pinia Agent Store 管理。

## 错误处理

- Base URL 无效时禁止请求并显示字段错误。
- 新配置未提供 API Key 时提示必填。
- HTTP 非成功状态统一转换为稳定的 Provider 错误。
- 响应缺少 data 或没有有效模型时显示“未获取到模型”。
- 请求失败后保留表单内容和上一次成功获取的模型列表。
- 保存失败后不关闭页面，不清空 API Key 输入。
- 错误信息不得包含 API Key、Authorization Header 或完整 Provider 响应。

## 模块边界

- views/settings.vue：设置页布局和菜单。
- layouts/components/left/settings/index.vue：聊天页设置入口。
- components/settings/model-profile-settings.vue：配置列表、表单和模型选择。
- stores/agent.ts：配置摘要与模型查询状态。
- lib/agent-client.ts：类型化 Runtime 调用。
- agent-protocol：model/list schema 和共享类型。
- agent-runtime：密钥解析、Provider 请求和错误转换。

原聊天页右侧模型配置表单移除，避免重复入口。

## 测试

- 协议测试验证 model/list 参数。
- Runtime 测试使用本地假 HTTP 服务验证请求路径、Bearer Header、模型解析和错误脱敏。
- Store 测试验证加载、成功、失败和编辑时复用已有密钥。
- 页面交互验证设置入口、返回操作、配置新增与编辑、模型获取和保存。
- 浏览器或 Electron 验证 1440x900、1920x1080 下的布局、滚动、焦点和溢出。
- 返回聊天页后验证会话、输入草稿、滚动位置和面板状态不变。

## 验收标准

- 点击左下角“设置”后在当前窗口打开独立设置页。
- 设置页左侧只有“模型配置”菜单，右侧显示配置管理内容。
- 用户可以输入 Provider、Base URL 和 API Key，并手动获取模型。
- 模型请求由 Runtime 执行，Renderer 无法读取已保存的完整 API Key。
- 用户可以新增和编辑多个配置，并选择默认配置。
- 保存后聊天输入框显示最新模型选项。
- 返回聊天页后，进入设置前的聊天页面状态保持不变。
- 原右侧栏不再提供重复的模型配置表单。
