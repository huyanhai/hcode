# HCode 本地 Coding Agent 设计

## 状态

已获批准的设计。本文档定义首版本地 Coding Agent 的边界，不包含实现代码。

## 背景

仓库当前包含 Vue + Electron 客户端 `apps/client`。聊天界面已存在，但尚未接入模型、工具执行或会话持久化。目标是使用 Vercel AI SDK 构建类似 Codex 的本地 Coding Agent：用户配置模型后，在用户选择的工作区内读取和修改文件、执行命令，并通过前台查看流式进度和审批请求。

## 目标

- 支持用户选择本地 workspace 并创建多个会话。
- 支持多个模型配置档，并在每次发送前切换。
- 使用 Vercel AI SDK 运行模型和工具循环。
- 持久化会话、消息、turn、工具调用、审批和完整 Agent 事件。
- 支持文件读取、搜索、写入、补丁、命令执行和 Git 只读操作。
- 对写操作和命令执行提供用户审批。
- 支持流式输出、取消、应用重启后的历史恢复。
- 保持 Agent Core 不依赖 Electron，未来可复用于 CLI 或远程 Runtime。

## 非目标

- 首版不提供云端 Agent 服务或多用户协作。
- 首版不自动重放应用重启前未完成的工具调用。
- 首版不提供复杂插件市场、子 Agent 或跨设备同步。
- 首版 API Key 明文存储在本地 SQLite；后续通过接口替换为加密存储或系统钥匙串。

## 总体架构

```text
apps/client
  Vue Renderer
      │ typed preload API
      ▼
  Electron Main
      │ JSONL RPC
      ▼
apps/agent-runtime
  Runtime process
      ├── agent-core
      ├── local tools
      └── SQLite repository
```

Renderer 不直接调用 Vercel AI SDK，不直接访问 Node 文件系统，也不直接访问 SQLite。Electron Main 负责窗口和受限 IPC；Agent Runtime 独占会话数据库、模型密钥和本地工具执行。

## Workspace 与会话

Workspace 是用户通过原生目录选择器主动选择的本地目录。它是所有文件工具、Git 操作和命令执行的根边界。

```text
Workspace = Agent 可访问的目录边界
Session   = 绑定一个 Workspace 的持续对话
Turn      = Session 中的一次用户请求和执行过程
```

一个 workspace 可以包含多个 session；一个 session 只绑定一个 workspace。创建或打开 session 前必须已有 workspace。

工具层必须规范化绝对路径、检查 `..` 路径和符号链接，禁止访问 workspace 外部路径。命令的默认 `cwd` 是 workspace root 或其受校验的子目录。

## 包结构

```text
packages/agent-protocol
  Command、AgentEvent、错误码和 Zod schema

packages/agent-core
  ToolLoopAgent、上下文、stopWhen、prepareStep、审批策略

packages/agent-storage
  SQLite repository、迁移和事务封装

packages/agent-tools-local
  文件、搜索、Shell 和 Git 工具

apps/agent-runtime
  Runtime 进程、JSONL RPC、会话管理和进程生命周期

apps/client
  Vue UI、Electron Main、Preload 和 LocalAgentTransport
```

依赖方向为 `client -> agent-protocol`；`agent-runtime -> agent-core/agent-storage/agent-tools-local`；`agent-core -> agent-protocol`。 `agent-core` 不依赖 Electron。

## 模型配置

支持多个 `model_profiles`。每次发送消息前由用户选择一个配置档；正在执行的 turn 不允许切换配置。

配置档包含：

- `name`
- `provider`
- `model`
- `base_url`
- `api_key`
- `is_default`

首版 API Key 与普通配置一起明文存放在本地 SQLite，但只允许 Runtime 读取完整值。Renderer 只获取配置摘要和脱敏值。API Key 不进入消息、Agent 事件、工具调用输出或日志。

未来通过以下接口切换存储方式，不修改 Agent Core：

```ts
interface CredentialStore {
  get(profileId: string): Promise<string | null>;
  set(profileId: string, apiKey: string): Promise<void>;
  delete(profileId: string): Promise<void>;
}
```

## 数据模型

SQLite 至少包含以下表：

```text
workspaces
model_profiles
sessions
turns
messages
agent_events
tool_calls
approval_requests
```

`turns` 固化本次实际使用的 `profile_id`、`provider`、`model` 和 `base_url`，不复制 API Key。这样修改或删除模型配置后，历史记录仍可追溯。

`messages` 是前台展示投影；`agent_events` 是完整、按 session 递增序列的事件日志。事件表使用 `(session_id, sequence)` 唯一约束，支持断线恢复和重放。

## Agent 与事件流

Agent Core 使用 Vercel AI SDK 的 `ToolLoopAgent`、`stream`、`stopWhen`、`prepareStep` 和工具审批能力。SDK 只负责模型调用与 Agent Loop；Runtime 负责持久化、权限、进程和恢复。

每个事件的处理顺序为：

```text
模型或工具产生事件
  → Runtime 在 SQLite 写入事件
  → 写入成功后推送 AgentEvent
  → Renderer 更新 UI
```

建议的事件类型包括：

```text
turn/started
message/delta
tool/call-created
tool/progress
tool/completed
approval/requested
approval/responded
turn/completed
turn/failed
turn/interrupted
```

前台打开会话时先读取数据库消息，再从最后一个事件 `sequence` 订阅后续事件。

## Runtime 协议

Command 和 Event 均通过 JSONL 传输，并使用共享的 Zod schema 校验。

```ts
type Command = {
  requestId: string;
  type:
    | "profile/list"
    | "session/list"
    | "session/open"
    | "turn/start"
    | "turn/interrupt"
    | "approval/respond";
  payload: unknown;
};

type AgentEvent = {
  eventId: string;
  sessionId: string;
  turnId?: string;
  sequence: number;
  type: string;
  payload: unknown;
};
```

每个 Command 具有 `requestId`，Runtime 对重复请求做幂等处理。审批响应必须绑定 `toolCallId`、工具名称和输入摘要，Runtime 在执行前再次校验实际参数。

由于 Runtime 是独立进程，客户端使用自定义 `LocalAgentTransport`，而不是直接使用 AI SDK 的 `DirectChatTransport`。未来可以增加 HTTP 或 WebSocket Transport，UI 不需要改变。

## 工具与权限

首版工具：

```text
listFiles、readFile、searchFiles
writeFile、applyPatch
execCommand
gitStatus、gitDiff、gitLog
```

只读文件工具和 Git 只读工具默认自动执行；写文件、应用补丁和执行命令需要用户审批。删除操作、Git 修改操作和外部网络操作首版默认不提供，或必须强制审批。

所有工具都接收 Runtime 注入的 workspace、session 和 turn 上下文。命令执行必须限制 `cwd`、超时、输出长度，并在超时后终止整个进程树。

## 生命周期与恢复

- 已完成 session 可以在应用重启后继续。
- `running` 状态的 turn 在 Runtime 启动时标记为 `interrupted` 或 `crashed`。
- 不自动重放未完成的工具调用。
- 已完成工具调用保留输入、输出和状态。
- 用户可以重新发送消息或继续说明。
- 用户主动停止的 turn 标记为 `cancelled`。

## 错误处理

错误需要使用稳定错误码，而不是把底层异常直接发送到 Renderer。至少覆盖：模型配置缺失、Provider 请求失败、工具参数无效、workspace 越界、审批拒绝、命令超时、Runtime 崩溃和数据库错误。

工具失败必须记录 `tool_calls.status` 和可展示的错误摘要；原始 API Key、Authorization header 和敏感环境变量不得进入错误事件。

## 测试策略

- `agent-core`：使用内存仓储和假模型测试工具循环、停止条件和审批。
- `agent-storage`：测试迁移、事务、事件序列、会话恢复和幂等写入。
- `agent-tools-local`：测试路径穿越、符号链接、命令超时和输出限制。
- `agent-runtime`：启动真实子进程，测试 JSONL RPC、取消、崩溃标记和断线恢复。
- `apps/client`：测试配置切换、消息流渲染、审批交互和会话重开。

## 首次实现顺序

1. 建立 `agent-protocol` 和 SQLite schema/migrations。
2. 实现 model profile、workspace、session 和 turn repository。
3. 实现 Runtime JSONL RPC 和进程启动/停止。
4. 接入 `ToolLoopAgent` 与只读工具。
5. 接入写文件、命令执行和审批恢复。
6. 将客户端本地消息列表替换为 `LocalAgentTransport`。
7. 增加恢复、错误、权限和 Electron 打包测试。

## 验收标准

- 用户可以选择 workspace、创建 session 并发送消息。
- 用户可以在多个模型配置之间切换，新 turn 使用选中的 profile。
- 模型可以读取工作区文件并流式返回结果。
- 写文件和命令执行会产生审批请求，拒绝后不会执行工具。
- 应用重启后可以查看并继续历史 session。
- Runtime 崩溃或窗口关闭不会导致未完成工具自动重复执行。
- 所有文件和命令操作都不能越过 workspace root。
- API Key 不出现在 Renderer、事件日志和普通日志中。
