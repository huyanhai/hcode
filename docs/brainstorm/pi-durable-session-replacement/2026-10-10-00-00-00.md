# Pi Durable 会话替换设计

## 目标

用 Pi Durable 的 `Conversation` 替换 hcode 的 Prisma `Session` 和 `Message`。Pi 存储成为会话、消息、工具执行、审批、队列和任务状态的唯一来源。不迁移现有会话记录。

支持两类会话：

- 持久会话使用一个共享 Pi SQLite store。应用重启后恢复未完成的任务和等待中的消息。
- 临时会话使用 `MemoryStorage`。进程退出后丢弃其记录和任务。

Pi 的标准 `CodingTools` 提供 `read`、`write`、`edit` 和 `bash`。hcode 不再维护同名工具或模型工具循环。

## 范围

保留现有 `/api/sessions` 路由与 Vue 数据形状，内部改为 Pi adapter。会话 ID 改为 Pi Conversation ID。

保留：会话创建、列表、归档、打开、发送、SSE、审批、工作区绑定、模型选择、附件和批注。

移除：Prisma `Session` 与 `Message` 作为会话事实来源，`agent-core` 的执行循环，`agent-tools-local` 的文件和命令工具定义，内存中的 `pendingApprovals`。

本次不保留旧会话，也不实现临时会话转持久会话。

## 架构

```text
Nest SessionsController
  -> PiSessionService
       -> durableHarness: Pi SQLite Storage
       -> ephemeralHarness: Pi MemoryStorage
       -> Pi Conversation
            -> CodingTools + guarded Node ExecutionEnv
            -> Pi event stream
  -> SSE adapter
  -> existing Vue client
```

`PiSessionService` 在应用启动时打开持久 Harness、安装 Pi 标准工具和 hcode policy extension，然后调用 `resume()`。它在应用关闭时关闭两个 Harness。临时 Harness 在首次创建临时会话时建立；内存会话只在本进程有效。

每个 Pi Conversation 带一个 hcode session document，字段为：`title`、`workspaceId`、`workspacePath`、`folders`、`persistence`、`status`、`createdAt` 和 `updatedAt`。该 document 和 Conversation 在同一 Pi commit 中创建或更新。Prisma 仅继续保存工作区、模型配置和文件存储，不再保存会话数据。

持久 SQLite 文件由 `HCODE_PI_SESSION_DB` 指定；未设置时放在服务器数据目录下的 `pi-sessions.sqlite`。应用启动时若文件不可用，服务不得静默降级为内存存储。

## 消息与等待

发送消息时，adapter 将请求转换为 `Conversation.submit()`：

- 空闲会话立即开始 GenerationTask。
- 忙碌会话默认传 `whenBusy: "followUp"`，由 Pi inbox 持久化排队。
- 显式 steer 使用 `whenBusy: "steer"`，在当前工具轮结束后加入当前运行。
- 等待模型完成使用 Pi `Submission.wait()`；HTTP 连接断开只取消观察，不取消 Pi 中已提交的工作。

SSE 直接传递 `watchEvents()` 产生的 Pi `AgentEvent`（`message_update`、`message_end`、`tool_execution_*`、`run_end` 等），不再在后端重新定义同义的 `text`、`tool-call` 或 `tool-result` 协议。只有附件/批注审批和流结束错误等 hcode 专属能力使用 `hcode.*` 扩展事件。客户端根据 Pi 事件维护 UI 状态，重新打开会话时仍以 Pi view state 为准，不依赖 SSE 重放。

思考内容是流期间的临时 UI 状态：客户端只消费 `thinking_delta`，在最终 `run_end` 或 `hcode.done` 后清空；投影和历史消息不保存思考内容，避免内部提示或模型思考泄漏到已完成消息中。

## 附件与批注

附件仍先经现有文件服务上传。每条用户输入在 Pi `pi.user` entry 中保存附件元数据：ID、URL、名称、MIME 类型和大小；批注保存为同一 entry 的 hcode metadata。

- 图片文件转换为 Pi `ImageContent`，并与用户文本一起进入模型输入。
- 非图片文件不伪装成模型原生文件。输入中加入其名称、MIME 类型和受控 URL；后续由 Pi `read` 工具读取已授权的本地工作区文件。远程上传文件在未引入受控下载工具前只作为元数据和用户可见附件保留。
- 批注转为紧邻用户文本的明确上下文块，同时保留结构化 metadata 供 UI 渲染。

助手消息、工具调用和工具输出完全从 Pi entries 与 `pi.live` 映射。UI 不读取 Pi 内部表，也不访问执行器内存。

## 工具、权限与审批

每个 Conversation 配置 Pi 的 `CodingTools`，并由 `NodeExecutionEnv` 提供运行环境。hcode 的 environment adapter 负责：

- 将 cwd 设为会话工作区。
- 拒绝主工作区之外的路径；附加目录按当前显式访问规则单独授权。
- 在会话 abort、Harness 关闭和命令超时时终止子进程。

policy extension 在 `ToolTask.beforeTool` 中实施权限：restricted 模式拦截写入、编辑和 bash；full 模式直接执行。审批记录必须写进 Pi state，批准或拒绝后唤醒原 ToolTask；服务重启后继续等待，不使用内存 Map。

## API 与模型适配

现有 HTTP 路由和 DTO 保持稳定。`CreateSessionDto` 增加可选 `persistence: "durable" | "memory"`，默认 `durable`。列表和详情响应增加 `persistence`，其余字段兼容现有客户端。

`ModelProfile` 由 adapter 转为 `pi-ai` 的 provider 与 model reference。实现前必须用当前 OpenAI Responses、Chat Completions 兼容配置各做一次无工具与工具调用验证。若某配置不能由 `pi-ai` 支持，创建或发送请求要返回明确的 4xx 错误，不得回落到旧 agent loop。

## 迁移与数据处理

部署时不读取、不导入旧的 Prisma `sessions` 和 `messages`。旧表保留在数据库中但不再被应用访问；后续单独安排数据库清理迁移。新会话不写入这些表。

现有客户端选择的旧会话 ID 返回 404，并由客户端创建新会话。测试数据库在切换后不应假设 Prisma 中存在会话或消息记录。

## 验收

1. 创建、归档、列出和打开持久/临时会话均只经过 Pi Conversation。
2. SQLite 会话在服务重启后保留 entry、运行状态、队列和审批；内存会话不保留。
3. 图片附件进入模型输入；所有附件和批注在重新打开会话后仍可渲染。
4. Pi CodingTools 执行 read、write、edit、bash，restricted 模式会持久化等待审批。
5. 断开 SSE 后重新连接或打开会话能得到已提交状态。
6. follow-up 与 steer 消息在重启后按 Pi inbox 语义继续执行。
7. 不存在对 Prisma `Session`、`Message`、`streamAgent`、`agent-tools-local` 或 `pendingApprovals` 的运行时依赖。

## 风险与门禁

Pi Durable 是实验性 ESM 包，固定使用 `@earendil-works/pi-durable@1.1.0` 及其配套包，并通过 adapter 隔离所有 Pi 类型。运行时最低 Node 版本提升至 `22.19`。Nest server 当前是 CommonJS，Pi Harness 放入 ESM runtime 边界；该边界必须先通过构建和启动测试，之后再删除旧执行链路。
