# 多目录按需访问

## 背景

项目可以配置一个主文件夹和多个附加文件夹。当前会话只使用主文件夹，导致用户无法在对话中读取附加文件夹。目标是保留主文件夹的默认行为，并在用户明确提出需求时访问附加文件夹。

## 目标

- 会话默认只读取、搜索和操作主文件夹。
- 用户明确点名附加文件夹或请求其内容时，会话可以访问该文件夹。
- 附加文件夹仍受工作区路径边界保护，不能访问未配置的路径。
- 同名文件夹和同名文件不会造成路径歧义。
- 保持现有单目录项目和会话行为兼容。

## 非目标

- 不把所有附加文件夹自动合并到默认搜索结果。
- 不修改用户本地目录结构，也不创建符号链接。
- 不提供让模型任意选择机器上其他目录的能力。
- 不改变项目编辑界面的多文件夹管理流程。

## 方案

### 会话上下文

工作区上下文从单一 `workspaceRoot` 扩展为主目录和附加目录集合：

- `primaryRoot`：项目的主目录，对应现有 `workspace.path`。
- `additionalRoots`：项目中除主目录外的已配置目录，每项包含稳定标签和绝对路径。

服务层从 `workspace.folders` 解析这些目录，并在创建会话、普通流式会话和审批恢复会话时传入相同上下文。旧数据没有 `folders` 时，使用 `workspace.path` 作为唯一主目录。

### 工具行为

现有文件、搜索、写入、补丁、命令和 Git 工具继续绑定 `primaryRoot`。因此模型未明确请求附加目录时，工具行为与现在一致。

新增附加目录工具，包含按标签列出文件、读取文件、搜索文本、写入文件、应用补丁和执行命令。附加目录工具接收目录标签和目录内相对路径。模型只能选择上下文中已注册的标签。写入、补丁和非只读命令继续遵循现有审批规则；只读操作不增加额外审批。

系统提示明确说明：附加目录默认不可见，只有用户明确要求访问某个附加目录时才调用附加目录工具。工具描述同时列出可用标签，便于模型将用户语言映射到稳定标签。

### 路径与安全

- 每个根目录分别执行 `realpath` 边界校验。
- 附加目录内的路径必须是相对路径；绝对路径、`..` 越界路径和符号链接逃逸全部拒绝。
- 未注册标签、已删除目录和不存在的目标文件返回清晰的工具错误，不回退到主目录。
- 搜索结果带上目录标签和相对路径，例如 `书籍/第一章.md`，避免同名文件混淆。
- 命令的工作目录只允许是主目录或已注册的附加目录内路径。

## 数据流

1. 会话服务读取工作区的主路径和 `folders` 配置。
2. 服务将主目录与附加目录映射构造成 `AgentContext`。
3. 智能体创建默认工具和附加目录工具；默认工具只绑定主目录。
4. 用户提及附加目录时，模型选择对应的附加目录工具。
5. 工具按标签解析根目录，校验路径边界后执行操作。
6. 流式会话暂停审批或恢复审批时复用同一份上下文。

## 错误处理

- 工作区目录不可读：会话在工具调用时返回现有文件系统错误格式。
- 附加目录标签不存在：返回“附加目录未配置”并列出可用标签。
- 文件或目录不存在：返回“路径不存在”，不尝试其他根目录。
- 路径越界：返回工作区边界错误，不执行操作。
- 附加目录配置重复：服务层去重；主目录重复项不注册为附加目录。

## 测试与验收

### 工具层

- 默认 `listFiles`、`readFile`、`searchFiles` 只能访问主目录。
- 附加目录工具能按标签读取、搜索和列出附加目录内容。
- 附加目录写入、补丁和命令遵循审批模式。
- 未知标签、路径越界、符号链接逃逸和不存在路径均被拒绝。
- 两个目录存在同名文件时，结果保留正确的目录标签。

### 服务层

- 多目录工作区创建和更新后，普通会话使用完整目录上下文。
- 审批暂停后恢复仍使用相同的主目录和附加目录集合。
- 只有主目录的旧工作区行为不变。

### 验收场景

1. 项目配置 `git` 为主目录、`书籍` 为附加目录。
2. 用户询问主目录文件，模型只使用默认工具并成功读取。
3. 用户询问“书籍目录中有哪些文件”，模型调用附加目录列举工具并返回 `书籍/...` 路径。
4. 用户要求读取 `书籍/目录.md`，模型成功读取；未提及附加目录时不会扫描该目录。
5. 用户要求访问未配置目录，模型收到明确错误且不会越界访问。

## 实施边界

改动集中在 `agent-core` 的上下文与工具注册、`agent-tools-local` 的多根目录解析，以及服务层构造会话上下文和测试。客户端项目编辑界面无需改动。
